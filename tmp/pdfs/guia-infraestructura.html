PARA USO GENERAL

La infraestructura en pocas palabras

Es el conjunto de piezas que permite que una aplicación reciba solicitudes, guarde información, procese tareas y muestre con claridad si todo está funcionando.

Una puerta de entrada

Traefik recibe todas las solicitudes. Es la recepción: dirige cada pedido al servicio correcto y evita sobrecargas.

Dos servicios

La aplicación se divide en dos servicios de prueba. Así se valida que componentes distintos puedan trabajar de forma coordinada.

Memoria y datos

PostgreSQL conserva la información importante. Redis acelera consultas frecuentes para que la respuesta sea más rápida.

Trabajo en segundo plano

RabbitMQ lleva mensajes entre servicios. Esto permite continuar un proceso sin obligar al usuario a esperar.

Cómo viaja una solicitud

Persona o sistema → puerta de entrada → servicio adecuado → datos o mensaje → respuesta. Mientras tanto, el entorno registra lo que ocurre para facilitar la operación.

Qué se gana

Orden: cada componente tiene una responsabilidad clara.   Velocidad: la cache evita trabajo repetido.   Confianza: métricas, registros y trazas ayudan a detectar y explicar incidentes.

Arquitectura y flujos

Un único proyecto Docker Compose organiza los componentes en la red interna demo-observability-net. Los microservicios no exponen puertos al host.

Reglas de exposición

Solo Traefik publica la API en :8000. PostgreSQL, Redis y RabbitMQ publican sus puertos en localhost para desarrollo; los servicios de aplicación permanecen internos. El gateway aplica 10 solicitudes/s por IP, ráfaga de 20 y hasta 50 solicitudes simultáneas por defecto.

Observar, diagnosticar, actuar

La observabilidad permite pasar de una alerta general a la causa concreta sin adivinar.

Métricas
Prometheus

¿Cuánto tráfico, error o latencia hay?

Trazas
OpenTelemetry → Tempo

¿En qué paso se demoró o falló la solicitud?

Logs
OpenTelemetry → Loki

¿Qué detalle explica el evento?

Grafana: una vista unificada

Grafana conecta Prometheus, Loki y Tempo. El identificador trace_id une una respuesta, su traza y sus logs: primero se detecta el problema en métricas, luego se ubica en la traza y por último se explica con registros.

Límites actuales y siguiente paso

Es un entorno de demostración y desarrollo: el dashboard de Traefik usa configuración insegura, no hay autenticación ni TLS, y los secretos parten de valores de ejemplo. Para producción, priorizar gestión de secretos, TLS, autenticación, endurecimiento de accesos, versionado inmutable de imágenes y alta disponibilidad.
